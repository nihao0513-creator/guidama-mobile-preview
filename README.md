# 귀담아 모바일 시험판

PC가 꺼져 있어도 휴대폰 자체 저장소에 녹음 조각, 전사문, 수정한 회의 보고서, 후속 업무를 보관하는 설치형 웹앱(PWA) 시험판입니다. v0.7에는 같은 Wi-Fi의 PC판과 연결 코드로 직접 동기화하는 시험 기능이 있으며, PC·휴대폰의 동기화 조작부는 각각 **설정** 메뉴에 있습니다. 모바일의 기기 내 전사 모델 준비와 선택 기록의 ZIP 백업도 설정으로 옮겼습니다. 음성·전사문은 외부 동기화 서버로 올리지 않고 LAN에서 AES-GCM으로 암호화해 주고받습니다. 실제 Android에서 QR 연결과 1회 동기화 완료는 사용자가 확인했습니다. 자동 재접속, 장시간·화면 잠금 녹음과 오프라인 전사는 아직 검증되지 않았으므로 최종 설치판으로 안내하지 않습니다.


## 휴대폰 시험 주소와 사용 흐름

https://nihao0513-creator.github.io/guidama-mobile-preview/

Android Chrome에서 열어 앱 설치 또는 홈 화면에 추가합니다. 처음에는 **현재 회의**가 열려 새 회의 녹음·파일 가져오기와 선택한 기록의 전사·보고서·업무가 표시됩니다. 메뉴는 **현재 회의 → 회의 기록 → 보관함 → 설정** 순서이며, 회의 기록 목록에서 기록을 누르면 현재 회의로 이동합니다. **보관함**에서는 보관함별로 기록을 찾고 이름을 관리하며, **설정**에서는 PC 연결·모델·ZIP을 관리합니다. 녹음 → 기기 내 전사 → 전사문 저장(버튼 옆 저장 결과 확인) → 전사문으로 요약 초안 만들기 → 보고서 저장 시 보관함 선택 → 후속 업무 확인 순서입니다. 보관함 만들기·이름 수정·삭제, 미분류·전체 조회와 기록 이동을 지원합니다. 기존 휴대폰 기록은 IndexedDB 버전 3으로 업그레이드해 유지합니다. 다만 실제 Android의 장시간·화면 잠금 녹음은 미검증입니다.

**설정 → 음성·기록 ZIP 백업**에서 기록을 선택하면 `record.json`(전사문·요약·할 일·보관함 이름 포함)과 `audio/segment-...` 음성 조각을 묶습니다. 기록만 JSON 내보내기 버튼은 제거했습니다. 저장 위치는 브라우저 설정에 따라 다르며 Android에서는 보통 파일 앱의 다운로드 폴더입니다. 내보내기 버튼은 동기화가 아닙니다. **설정 → PC 연결** 화면의 동기화 버튼을 별도로 사용합니다. PC에서 가져온 기록의 원음이 휴대폰에 없다면 ZIP 백업을 누를 때 크기를 확인받고 PC에서 내려받아 백업합니다. PC가 꺼져 있거나 저장 공간이 부족하면 ZIP 생성이 실패할 수 있으며 기존 기록은 유지됩니다. 다운로드 요청 메시지는 실제 파일 저장 완료를 보증하지 않으므로 파일 앱에서 확인하세요.

## PC 연결 시험

1. PC판 `http://localhost:4387/`의 **설정 → 연결 켜기**를 누릅니다. **연결 코드 보기 → 휴대폰 QR 보기**를 눌러 휴대폰 기본 카메라로 QR을 스캔하면 공개 앱에서 주소·코드가 자동으로 채워집니다. 수동 입력도 가능합니다. QR에는 연결 코드가 들어 있으므로 다른 사람에게 보여주지 마세요. PC의 기존 보관함과 완료 기록이 기준입니다.
2. 휴대폰 **설정 → PC 연결**에서 **PC 연결 저장·동기화**를 누릅니다. Chrome이 로컬 네트워크 접근을 묻는다면 허용합니다. PC와 휴대폰은 같은 Wi-Fi여야 하며 PC 방화벽은 **사설 네트워크만** 허용해야 할 수 있습니다. QR의 민감한 연결 정보는 URL의 서버 전송 대상이 아닌 fragment에 담고 앱이 열리자마자 주소창에서 지웁니다.
3. 휴대폰은 PC가 꺼져도 계속 기록합니다. PC가 다시 켜지면 **지금 동기화**를 누르거나 로컬 네트워크 권한이 허용된 상태에서 앱을 다시 엽니다. IP가 바뀌면 PC 화면의 새 주소를 입력합니다.
4. PC의 보관함·전사문·보고서·업무가 휴대폰에 들어옵니다. PC 원음은 저장 공간을 위해 동기화만으로 자동 내려받지 않으며 **설정 → 음성·기록 ZIP 백업**을 선택할 때 확인 후 가져옵니다. 휴대폰 음성은 PC로 구간별 전송됩니다. 동일 기록을 양쪽에서 수정하면 자동 덮어쓰지 않고 별도 사본으로 보존할 수 있습니다.

연결 코드는 휴대폰 IndexedDB에 저장되며 기기 접근 권한이 있는 사람에게는 보일 수 있습니다. 앱 삭제나 브라우저 데이터 삭제는 휴대폰 기록 손실 위험이 있습니다. PC 서버 `4387`은 계속 `127.0.0.1` 전용이고, 별도 연결 포트 `4392`만 연결을 켰을 때 사설 IP에 바인딩됩니다. 다른 브라우저나 버전에서는 HTTPS→HTTP LAN 요청이 차단될 수 있습니다.

## 로컬 실행

`node dev-server.js` 후 PC에서 `http://localhost:4390/`에 접속합니다. 외부 접속은 받지 않습니다. 처음에는 온라인 상태에서 **설정 → 기기 내 전사 모델 → 한국어 전사 모델 준비**를 눌러 다국어 Whisper Tiny 모델을 내려받습니다. 앱 화면, 실행용 JavaScript·WASM은 서비스 워커에 저장합니다. 모델은 브라우저 Cache Storage에 저장됩니다. 데이터는 IndexedDB에 평문으로 남으며, 브라우저 데이터 삭제·저장 공간 부족 때 사라질 수 있으므로 `음성·기록 ZIP 백업`을 사용하세요.

## 확인한 범위

- 390px 브라우저 화면, 합성 파일 가져오기, 전사문·규칙 기반 검토 초안·업무 저장, 새로고침 후 완료 체크 유지.
- 합성 오디오 스트림을 10초마다 IndexedDB에 저장하고 30초 단위 파일 두 개를 생성·개별 디코딩했습니다. 실제 휴대폰 마이크와 화면 잠금은 미검증입니다.
- 브라우저에서 온디바이스 Whisper Tiny 모델을 로드하고 합성 신호를 전사했습니다. 무음에서도 허위 문장이 생성되어 매우 작은 소리의 구간은 전사를 건너뛰고 표시하도록 했습니다. 음성 품질은 검증되지 않았습니다.
- 개발 서버를 끈 상태에서 앱 화면과 IndexedDB 기록·업무가 재조회됐습니다. 휴대폰 비행기 모드·실기기 설치·전사 전체 오프라인은 미검증입니다.
- ZIP 백업 생성기의 메타데이터·음성 파일을 Windows에서 압축 해제해 비교했습니다.
- 격리된 PC 합성 데이터와 데스크톱 브라우저 `localhost` 시험에서 보관함·기록 왕복, 30만 바이트 음성 전송, PC 원음 내려받기, 재접속, 수정 충돌 보존, PC 오프라인 삭제 차단을 확인했습니다. 공개 HTTPS 주소의 실제 Android QR 연결·1회 동기화 완료는 사용자가 확인했으며, 데이터 완전성·자동 재접속은 독립 검증 전입니다.

## 외부 연결

음성 샘플은 휴대폰의 Worker로만 보내며 외부 전사 API를 호출하지 않습니다. 첫 모델 준비에는 Hugging Face에서 모델 파일을 내려받아야 합니다. 실행용 Transformers.js/ONNX Runtime JavaScript·WASM은 `vendor` 폴더에 보관합니다. 라이선스 고지는 vendor 폴더에 있습니다. 실제 Android 기기별 HTTPS→LAN 연결·권한·방화벽, 장시간·잠금 화면 녹음과 오프라인 전사는 남아 있습니다. 공개 저장소에는 앱 코드만 있으며 녹음·전사문·연결 코드를 올리지 않습니다.
